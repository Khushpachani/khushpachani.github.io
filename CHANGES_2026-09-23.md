### 5.2 GitHub token (used instead of a password)

1. GitHub → **Settings → Developer settings → Personal access tokens**.
2. **Fine-grained token:** repository `khushpachani.github.io`; permissions **Contents: Read and write**, **Workflows: Read and write**.
   *(or a classic token with the `repo` + `workflow` scopes)*
3. Save it in the system keyring so Git remembers it:

```bash
sudo apt install -y libsecret-1-0 libsecret-1-dev make gcc
sudo make --directory=/usr/share/doc/git/contrib/credential/libsecret
git config --global credential.helper /usr/share/doc/git/contrib/credential/libsecret/git-credential-libsecret
```

At the push prompt: **Username** `Khushpachani`, **Password** = the token.

```bash
# Clear a wrong saved token, then push again
printf "protocol=https\nhost=github.com\n\n" | git credential reject
```

Watch progress in the repo's **Actions** tab (green ✓ = live). Node.js is **not** needed on this PC.

## 7. Custom domain `suid0.in` (GoDaddy → GitHub Pages)

### 7.1 Before

GoDaddy **Forwarding** redirected `suid0.in` (301) to `khushpachani.github.io`. The address bar showed github.io, and HTTPS on `suid0.in` did not work.

### 7.2 GoDaddy changes

1. **Forwarding tab:** deleted the forwarding rule.
2. **DNS Records:** deleted the forwarding/parking A records (`15.197.142.173`, `3.33.152.147`, then `3.33.130.190`, `15.197.148.33`).
3. Added / edited:

| Type | Name | Data |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `khushpachani.github.io` |

Unchanged: NS, SOA, `_domainconnect`, `_dmarc`.
*(Optional AAAA / IPv6 for `@`: `2606:50c0:8000::153`, `…8001::153`, `…8002::153`, `…8003::153`)*

**Source of these IPs:** GitHub docs, "Managing a custom domain for your GitHub Pages site":
https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site
They match `dig +short khushpachani.github.io`.

### 7.3 Repo changes

- `public/CNAME` → `suid0.in`
- `package.json` → `"homepage": "https://suid0.in/"`
- `public/index.html` → `og:url` and `<link rel="canonical">` set to `https://suid0.in/`

### 7.4 GitHub settings

- Repo **Settings → Pages → Custom domain:** `suid0.in` → Save
- After the certificate is issued: tick **Enforce HTTPS**
- Recommended: verify the domain in your **profile** Settings → Pages (adds a TXT record) to prevent takeover.

### 7.5 Problem hit: `NotServedByPagesError` / "DNS check unsuccessful"

**Cause:** GoDaddy's two hidden **parking** A records (`3.33.130.190`, `15.197.148.33`) were still served next to GitHub's four IPs.
**Fix:** delete them in GoDaddy, wait about 10 min (TTL 600), then in GitHub click **Remove** on the custom domain, re-add `suid0.in` and Save.
After that GitHub showed *"TLS certificate is being provisioned"* (can take up to 24 h).

### 7.6 Result

| Typed in browser | Ends at |
|---|---|
| `suid0.in` / `www.suid0.in` | `https://suid0.in` |
| `khushpachani.github.io` | `https://suid0.in` |
| any `http://` | `https://` (once Enforce HTTPS is ticked) |

## 8. Everyday commands

```bash

# edit src/data/portfolio.ts (text) or src/index.scss (styles)
```

### Change the resume link

Edit `RESUME_ID` at the top of `src/data/portfolio.ts`
(the ID from `https://drive.google.com/file/d/<ID>/view`), then commit and push.

### Preview locally (optional — needs Node.js 18+)

```bash

npm start          # http://localhost:3000
npm run build      # production build in ./build
npm test           # run tests
```

### Check the domain / DNS

```bash
dig +short suid0.in                          # should be ONLY the 4 × 185.199.x.153
dig +short suid0.in @ns73.domaincontrol.com  # GoDaddy's own answer (source of truth)
dig +short suid0.in @8.8.8.8                 # Google's cached answer
dig +short www.suid0.in                      # should show khushpachani.github.io
curl -sI https://suid0.in | head -1          # HTTP/2 200 = HTTPS working
```
